# Writing

- Apply ISO 24495-1 plain language to all prose: PR descriptions, code comments, tickets, summaries and chat answers.
- Lead with the consequence for a person (customer, reviewer, on-call engineer), then the mechanism.
- Prefer concrete numbers and examples to abstractions ("refunds £1,600", not "corrects refund handling").
- When asked to explain something, give the shortest version that is still true, and offer more depth rather than front-loading it.
- Skills with their own voice guidance (e.g. `pr-description-improver`) build on these rules; they only need to state what differs.
